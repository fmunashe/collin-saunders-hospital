1Purpose & Objectives

This strategy defines how quality is assured across the HMS Outpatient, Inpatient, and Pharmacy modules. The goal is to guarantee that clinical and financial data remain accurate, that automated business rules behave correctly, and that the system is safe for a live hospital environment.

Quality priority: In a hospital system, data integrity outranks feature velocity. Stock counts, bed occupancy, and billing totals must always be correct — these are the most heavily tested areas.

4Automated Test Coverage

The automated suite (PHPUnit / Pest) protects the critical business logic. Current coverage:

SuiteScenarios Covered
PharmacyTestStock deduction on dispense; stock restoration on reversal; over-dispensing blocked; expired-medication blocked; prescription status auto-sync
InpatientTestBed occupied on admission; bed freed on discharge; double-booking prevented; bed reuse after discharge; inpatient flag
BillingTestInvoice number generation; line-total calculation; invoice total = sum of items; recalculation on delete; paid/partially-paid status derivation
Run the suite: php artisan test — executes against an in-memory SQLite database for speed and isolation. All tests must pass before any deployment.

Target Coverage Additions (ongoing)

  • Policy/permission tests per role (authorised vs forbidden actions)
  • Report generation & permission-gating tests
  • Visit-to-invoice generation action test
  • Medication administration stock-deduction test

6Test Data Strategy

  • Seeders generate a realistic dataset: departments, doctors, wards, beds, medications (including deliberately low/out-of-stock and near-expiry items), patients, visits, admissions, prescriptions, and invoices.
  • Edge cases are seeded intentionally: out-of-stock medication, expired stock, occupied beds, partially-paid invoices.
  • UAT uses anonymised data — no real patient PII in non-production environments.

8Entry & Exit Criteria

Entry (testing begins when)

  • Feature is code-complete and merged to the test branch
  • Automated unit/feature tests pass
  • Test environment is deployed and seeded

Exit (a release is ready when)

  • 100% of automated tests pass
  • No open Critical or High defects
  • All acceptance criteria for in-scope stories are met
  • UAT sign-off obtained for the phase

9UAT Approach

  1. BA prepares UAT scripts mapped to real hospital workflows.
  2. Hospital staff execute scripts on staging with anonymised data.
  3. Findings are triaged daily during the on-site UAT visit.
  4. Sign-off is recorded per module (Outpatient, Inpatient, Pharmacy).
